# 真实订单接入契约（待业务系统提供）

当前 `/api/agent/order` 仅是内部只读入口，对所有订单返回 503。旧公开 `/api/business/order` 返回 410。演示表 `orders` 的 `user_name` 不是客户身份，不能用于授权。

接入前先完成客户会话令牌：可信宿主在服务端验证登录状态后签发短期令牌，令牌至少绑定 `tenant_id`、不可变 `customer_id`、`session_id` 和有效期。Go 以令牌主体为准创建或读取会话，不能从浏览器传来的 `user_id` 或订单号推断归属。HTTP 历史、WebSocket、工单与订单查询必须共用该校验。现有租户级 `app_key` 令牌不足以证明访客身份。

只读订单适配器应接受 `(tenant_id, customer_id, order_id, trace_id)`，从真实业务系统返回已核验的订单状态与可展示字段。必须由业务系统或 Go 适配器在一次受控查询中同时校验租户和客户归属；跨租户、非本人和不存在的订单对用户统一返回“未找到可查询订单”，不泄露是否存在。不得以客户姓名、手机号末位或 LLM 推断作为归属证明。超时、业务系统错误、缺少身份、缺少归属字段一律拒绝返回订单详情，并留下 trace（避免记录完整 PII）。

验收至少覆盖：本人订单成功、同租户他人订单、跨租户订单、无效/过期令牌、订单不存在、业务接口超时、会话重放与重试；前端页面、Go、Python Agent 和真实业务 API 的结果要一致。

退款和支付仍需独立阶段：明确业务写接口、交易幂等键、订单状态重查、审批主体和审批记录、超时与重复审批处理、越权拒绝及审计。未达到这些条件，不注册可调用的写入工具或按钮。
