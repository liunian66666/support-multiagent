# 复合客服问题的只读编排

当一句话同时要求核对订单和解释知识库政策，或同时问两个独立知识主题时，Python Agent 使用受限任务计划执行。原有单一 FAQ、单一订单、转人工路径继续使用各自的快路径。

```text
可信租户与会话校验 → 原路由拦截转人工/退款/支付操作
                 → 至多 1 个订单读取 + 2 个知识库读取（并发、分别限时）
                 → 收集结果码与文档标题/ID/片段
                 → 1 次模型整理回答 + 知识来源
```

订单读取仍调用 Go 的只读接口，由服务端会话核验租户和客户归属；知识库只访问当前租户的检索器。订单号不会进入知识库查询。未提供订单号时可先回答有文档依据的政策部分，并请求订单号；同一会话下一轮直接回复订单号会继续原复合问题。知识库为空时不调用模型编造政策。订单归属核验失败或订单服务不可用时延续原自动转人工规则。任何退款、支付或退货操作请求仍由原路由转人工，本流程没有写业务工具。

目前计划器是有边界的规则拆解，支持订单核验与常见知识主题；它不是任意任务的自主规划器。知识库仍使用现有相似度检索，尚未建立相关性评测阈值。访客登录买家账号若生成新的 `thread_id`，未完成的复合问题不会跨会话续接。流式接口在并发取证和整理完成后发送最终 `end` 帧，因此首字延迟取决于最慢的读取与模型整理。

回归用例覆盖订单与政策并发、两个知识主题、缺订单号、同会话补订单号、知识库空、归属失败、单问题快路径和写操作拦截。尚需在部署环境以实际店铺知识库与买家会话验收回答正确性、响应时间和总 token 消耗。
