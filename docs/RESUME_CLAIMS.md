# 简历可写范围

建议只在能展示本仓改动和验收记录时使用下述表述：

> 在现有多租户客服项目中整合电商客服 Agent 的通用 FAQ 流程与回答边界：通过 Go 到 Python 的内部身份校验、租户知识库索引和来源标识，让前端 FAQ 回答可核验；将缺少客户归属证明的订单查询改为明确拒答，并关闭公开演示订单查询；修正转人工按钮与工单流程，实测前端建单、后台查询和会话消息落库。在此基础上完成多项优化：FAQ 由精确字典匹配升级为意图规则匹配（覆盖退货/退款/订单状态/能力四类意图及变体问法），转人工识别扩展至投诉等说法并区分建单原因，订单号上下文扩展至快递/物流/包裹；修复知识库索引后检索器不重建与向量删除条件失效两处缺陷，使重索引后服务无需重启、删除文档后向量真正清理；为演示租户补录示例政策文档，运费/时效/到账可检索作答；新增确定性答复（流程 FAQ / 订单核验 / 转人工）旁路写入 LangGraph 检查点，使长对话后续 LLM 能回忆确定性答复的上下文。

可以展示：`docs/MERGE_GOAL.md`、`docs/MERGE_ACCEPTANCE.md`、对应代码差异、测试输出（Python 单测 8 项 + 旁路图单测 3 项均通过）、Go 全量测试通过、`frontend-acceptance.png` 及端到端实测记录。

不应写成已经完成：真实订单查询、退款/支付业务闭环、客户级身份认证、公开商家政策 RAG 评测、原项目整体 SaaS 架构或未经测量的性能提升。
