# 公开演示站部署与隔离指南（云服务器 + 自有域名）

> 目标：在**一台自己的云服务器 + 自有域名**上，把本仓库跑成别人点开就能聊的 HTTPS 演示站，且不暴露管理端、不泄露密钥、不把模型额度刷爆。
> 本文只覆盖这一条路径。**所有启动动作由维护者自己执行**；模板不改动现有 `docker-compose.yaml`、`deploy/nginx.conf`、`.env` 与源码。

## 1. 服务器与域名前提

| 项 | 要求 | 检查方式 |
|---|---|---|
| 服务器规格 | Compose 会起 MySQL、PostgreSQL、Qdrant、Redis、business、maintenance、agent、nginx 共 8 个容器，建议 **4C8G / 40G 磁盘**起步 | `free -h`、`df -h` |
| Docker | Docker Engine + Compose **≥ v2.24.4**（`ports: !override` 需要）；本机验证时为 v5.6.1 | `docker compose version` |
| DNS | `demo.example.com` 的 A 记录指向服务器公网 IP，并等生效 | `dig +short demo.example.com` |
| 备案 | 域名指向**境内**服务器需完成 ICP 备案，否则 80/443 会被拦 | 云厂商控制台 |
| 安全组 / 防火墙 | 只放行 **22（限制来源 IP）、80、443**；`8080` 绝不对公网开放 | `ss -ltnp`、云安全组 |
| 系统包 | `nginx`、`certbot`（含 webroot 插件） | `nginx -v`、`certbot --version` |
| 证书续期 | 确认自动续期可用，避免 90 天后演示站证书过期 | `sudo certbot renew --dry-run` |

```bash
# Ubuntu 示例
sudo apt-get update
sudo apt-get install -y nginx certbot
sudo mkdir -p /var/www/certbot
```

## 3. 部署步骤

以下命令在服务器上、仓库根目录、**同一个 SSH 会话**里依次执行。先设好域名变量，后面配置与证书路径都用它替换：

```bash
DEMO_DOMAIN="demo.example.com"   # ← 改成第 0 节里的真实域名
```

### ① 拉代码并配置环境变量

```bash
sudo mkdir -p /opt/support-multiagent
sudo chown "$USER":"$USER" /opt/support-multiagent
git clone https://github.com/liunian66666/support-multiagent.git /opt/support-multiagent
cd /opt/support-multiagent

cp .env.example .env
# 按 deploy/demo/env.demo.example 逐项覆盖 .env（不要直接拿模板当 .env）
# openssl rand -hex 32   # 生成 MODEL_KEY_ENCRYPT_KEY / INTERNAL_API_TOKEN
```

### ② 申请证书（先只开 80）

正式 edge 配置引用 443 证书，证书还没申请时 `nginx -t` 会失败，所以先放一个只服务 ACME 校验的引导站点：

```bash
sudo tee /etc/nginx/conf.d/demo-bootstrap.conf >/dev/null <<'EOF'
server {
    listen 80;
    server_name demo.example.com;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 200 'ok'; }
}
EOF
sudo sed -i "s/demo.example.com/${DEMO_DOMAIN}/g" /etc/nginx/conf.d/demo-bootstrap.conf
sudo nginx -t && sudo systemctl reload nginx

sudo certbot certonly --webroot -w /var/www/certbot -d "${DEMO_DOMAIN}"
```

### ③ 启用正式 HTTPS 反代

```bash
sudo cp deploy/demo/nginx-edge.conf.example /etc/nginx/conf.d/demo.conf
sudo sed -i "s/demo.example.com/${DEMO_DOMAIN}/g" /etc/nginx/conf.d/demo.conf
# 停用引导站点（改名，不删除文件；nginx 只加载 *.conf）
sudo mv /etc/nginx/conf.d/demo-bootstrap.conf /etc/nginx/conf.d/demo-bootstrap.conf.disabled
sudo nginx -t && sudo systemctl reload nginx
```

`sed` 会同时替换 `server_name` 与 `ssl_certificate` 路径中的域名，两者必须一致。

### ④ 启动服务

```bash
docker compose -f docker-compose.yaml -f deploy/demo/docker-compose.demo.yaml up -d --build
docker compose -f docker-compose.yaml -f deploy/demo/docker-compose.demo.yaml ps
```

不启动 `observability` profile，Grafana/Prometheus/Loki 不会额外暴露。

### ⑤ 启动后两件必做事

1. **配置模型**：从内网/本地打开管理后台，在「平台模型配置」填对话模型 + Embedding 模型并测试连通性，否则 AI 不会应答。
   > 基础编排把 `FOUR_AGENT_EVAL=on`、`FOUR_AGENT_MODEL_NAME=glm-5.3` **硬编码**在 `agent.environment`，注释说明是演示环境用平台密钥顶替租户配置。公开演示时所有对话都会走这把平台密钥、费用集中；若要按租户自己的模型计费，需先改基础编排（本次模板未改动它）。接真实租户前必须移除这两行。
2. **设置租户配额**（字段在 MySQL `tenants` 表，不在 `.env`）：

```bash
docker compose -f docker-compose.yaml -f deploy/demo/docker-compose.demo.yaml exec mysql mysql -uroot -p cs_biz_db
```

```sql
-- 演示租户 t_demo；数值按预算调整，0 = 不限
UPDATE tenants
   SET daily_message_limit = 200,
       max_concurrent_sessions = 10,
       max_kb_docs = 5,
       max_kb_size_mb = 20
 WHERE tenant_id = 't_demo';
```

也可在内网打开管理后台的「租户配额」页修改——公网演示站已屏蔽 `/api/admin/`，该操作不能从公网站点完成。

## 4. 隔离与护栏清单

| 项 | 做法 | 为什么 |
|---|---|---|
| 唯一公网入口 | override 把 nginx 绑到 `127.0.0.1:8080`；安全组只放行 80、443 | 防止绕过 TLS 直连 8080 |
| 路径屏蔽 | edge 层 404 掉 `/admin/`、`/api/admin/`、`/py-api/api/admin/`、`/api/agent/`、`/py-api/api/agent/`、`/agent/`、`/metrics`、`/docs`、`/py-api/docs`、`/ws/admin` 等 | 管理端 API 与决策轨迹不能从公网访问；`/py-api/` 会 rewrite 到业务层、绕过内层的 `/api/agent/` 拦截，等价路径必须一并挡 |
| 真实 IP 透传 | `00-realip.conf` 挂载进内层 nginx；edge 层用 `proxy_set_header X-Forwarded-For $remote_addr` | 业务层限流只读 `X-Real-IP`，不做会把所有访客当成同一个 127.0.0.1，5 次失败全员锁 10 分钟 |
| 外层限流 | API `2r/s`、页面 `10r/s`、单 IP 20 并发 | Redis 登录限流之外的第一道闸，挡脚本刷量 |
| 业务配额 | `daily_message_limit` / `max_concurrent_sessions` + `CHAT_TURN_WORKERS=2` | 控制同时烧 token 的轮次与每日总量 |
| 演示开关 | 只留 `CS_AUTH_DEMO_CUSTOMER_LOGIN` 与 `CS_AUTH_DEMO_GUEST_CHAT`；`CS_AUTH_MERCHANT_PREVIEW_LOGIN=false` | 关掉带密钥的旧版商家预览链接 |
| 密钥与额度 | 全部换成随机值；平台模型密钥设消费上限，每日看用量报表 | 公网每轮对话都产生真实费用 |
| 日志与数据 | 内层 nginx 已有脱敏 `log_format redacted`；`MSG_RETENTION_DAYS=7`；演示数据定期重置 | 避免凭证落日志、消息无限堆积 |
| 演示边界告知 | 演示页/README 写明：2 条虚构订单、2 个源文档；演示客户登录只证明「签发了这个选择」，不是真实身份 | 不拿演示数据冒充真实业务能力 |

> `CORS_ALLOW_ORIGINS` 当前代码**未读取**，不要把它当安全护栏；演示站同源访问，保持为空即可。

## 附：Compose 版本过低（< v2.24.4）

`ports: !override` 是 Compose v2.24.4+ 的语法。低版本**不能**直接删掉 `!override` 启动——ports 会与基础编排合并，导致 `0.0.0.0:8080` 仍暴露。备选做法：

```bash
cp docker-compose.yaml docker-compose.demo.local.yaml   # 必须放在仓库根目录，相对路径才正确
# 手工把该副本 nginx.ports 改成 "127.0.0.1:${HTTP_PORT:-8080}:80"，
# 并在 nginx.volumes 追加 ./deploy/demo/00-realip.conf:/etc/nginx/conf.d/00-realip.conf:ro
docker compose -f docker-compose.demo.local.yaml up -d --build
# 该副本只用于本地演示，不要提交进公开仓库
```

版本检查：`docker compose version`。本机已用 `docker compose -f docker-compose.yaml -f deploy/demo/docker-compose.demo.yaml config --quiet` 验证 `!override` 生效，展开后 `nginx.ports` 仅 `127.0.0.1:8080→80`。
