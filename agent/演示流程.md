实测过的，可直接引用（详证见 [实际效果报告.md](实际效果报告.md) §4 §5 §6 §8f）。

## 第 1 幕：复合咨询——一轮里真的派了两个 Agent

```bash
bash agent/evaluation/run_all.sh demo-pg
```

先讲 `[1]` 这一行：`outcome=answered agents=faq,order attempts=1 evidence=1`，答复是
「订单 ORD-1001 已发货；退货请在签收后 7 天内申请，运费自理。」——一句话里**订单事实来自只读订单接口、
政策数值来自知识库证据**，两条来源在同一轮汇合。`ledger`/trace 里能逐条看出委派了谁，这不是提示词里
写着"你派了谁"，是状态通道里记着。

再说 `[4]`：这一次 checkpointer 是部署库上的真 `AsyncPostgresSaver`，本线程占 **161 行**，
`adelete_thread` 之后 **0 行**。同一支脚本用内存 saver 跑（`run_all.sh demo`）产出的 9 行逐轮记录
与 PG 臂 **sha256 相同**——换存储后端对产出的每一轮零影响，它只决定这些轮次能不能跨进程活下来。

## 第 2 幕：长对话续聊——水位线推进，一条转写都没丢

接着上面那条线程（同一个 `demo-*` key），`[2]` 段 8 轮之后：

```
水位线：total=18 summarized=12 verbatim=6 watermark=12
```

要点讲三句：① `summarized + verbatim == total`，压缩只是把旧轮**交给摘要通道**，转写一条不删；
② `watermark` 只前进不回退，所以"旧摘要覆盖新摘要"这条老 bug 在这张图里结构上不可能发生
（`test_memory.py` 里有专门钉它的用例，含**摘要失败不得越界**的对照组）；③ 摘要是**上下文不是事实来源**
——`[3]` 那行会把提示里那句"不作为订单状态或店铺政策的依据"打出来，`True` 就是它在。

如果被追问"记忆到底比旧路径好多少"：不要说"更好"，说**机制层面**——冻结十例的两列账本
（进模型上下文 / 仍可恢复）是 `window_only` 0/30 · 30/30、`delete_rebuild` 0/30 · **0/30（真丢了）**、
`watermark_norepair` 0/30 · 30/30、本实现（水位线＋锚点回补）**30/30 · 30/30**；
补的结构变体十一例把可见性从 9/33 抬到 33/33、波动从 3 收到 0（报告 §6a/§6b）。
而**答复质量**的对照需要真实模型，今天网关不给（见最后一节），所以这条只能讲机制，不能讲分数。

## 第 3 幕：安全边界与真入口（不发消息的那一半）

```bash
bash agent/evaluation/run_all.sh http        # 20 项：开关回退/越权 403/JSON=SSE/重放幂等/故障降级
bash agent/evaluation/run_all.sh guards      # 30 例对抗语料：0 漏放 0 误拦
bash agent/evaluation/run_all.sh xproc     # 跨进程并发：不加锁 12 轮只剩 3~4 轮，加 advisory 锁六批 80 轮零丢轮（§4b）
bash agent/evaluation/run_all.sh frontend    # 14 项：客户面根本到不了 agent
```

`http` 这一场最值得现场演的两句：跨租户线程 **403 且不落检查点**（归属在构图之前校验，不花钱、不写库），
以及模型抛异常时仍然 **200 + 非空白答复 + `error` 字段可见**（降级不是沉默）。
`guards` 讲的是"改写后的违规"——把「我们将在 7 天内退款」改成各种口语说法，仍然拦得住，
且 5 条良性对照零误拦。
`frontend` 是给"翻开开关会不会多暴露一张面"这个问题的答案：agent 容器没有宿主端口、边缘三条 `/agent/*` 全 404。

## 如果对方追问"app 侧那张自己挂起来的图呢？你也只能指出问题，有没有修法？"

这一条现在有可执行的答案，而且**不碰生产代码**：

```bash
bash agent/evaluation/run_all.sh mounted-fixed   # ~2 分钟，四个容器；退出码 0
```

它把三份候选补丁只打在 `.tmp_eval/` 下的临时副本上（工作树 `python_agent/` 一字未动，镜像不重建），
然后**对照组与补丁组用同一把尺子各跑一遍**，出两张表：

- 30 例对抗语料：corpus 漏放 **9→0**、backed 漏放 **22→0**、误拦 **0**（`GATE PASS`）。
- 挂载图 12 个 case 逐题差异：**修好 2**（`M2b_replay_with_turn_id`：同一 `turn_id` 重放不再多一条人消息、
  不再多记账；`M5b_failure_state_and_visibility`：故障轮不再留下无人回答的人消息，原因既进了 `last_error`
  通道、也在**故障那一轮自己**的 trace 里留下事件 `failure_turn_error_events 0→1`）、
  **回退 0、缺题 0**；观测列里有几处变化，其中一处是成本——M2 的 `billed_msgs_per_turn 2→4`，
  规则收紧的代价，现场就把这行念出来，别只报好消息。M10/M11 归"竞态"：两臂都在丢（5 次试验丢 1~4 次），
  补丁没碰那条路径，所以不参与回退判定——跨进程这件事是 §4b 用 advisory 锁单独解决的。

被追问"那为什么不开开关"时的说法：**这补的是能力，不是入口契约**。`ChatRequest` 里仍然没有 `turn_id`
字段，前端/代理不带键，走的就是今天的路径；M3 是**故意没出补丁**（要让它可见就得在图外补写检查点，
正是阶段3 要取消的那件事，见报告 §5i），M10/M11 是平台层性质、补丁没碰那条路径（`agent/` 那条路的跨进程
丢轮已经用 advisory 锁实测修好，见 §4b）。所以开关继续留 off，落地顺序写在 `deploy/README.md` 的"什么会改变先别开的结论"。

## 如果对方问"新链路和旧链路谁答得更好"

现在有实测答案了，而且是**同一个真实模型**跑的（报告 §8g）：

| 臂 | 36 题字面通过 | 延迟 p50 | token 合计 |
| --- | --- | --- | --- |
| 旧路径（开关 off） | **35/36**（闸门尺子 34/36） | **3.4s** | 43.3k |
| 新四 Agent 图 · 第 1 次 | 34/36 | 7.8s | 149.3k |
| 新四 Agent 图 · **同臂串行复跑** | **33/36** | 8.5s | 175.6k |

现场就这么说：**质量不可区分，成本新图更贵——延迟 2.3~2.5 倍、token 3.4~4.1 倍**。
为什么不说"新图差 1 题"：同一臂串行复跑第二次是 **33/36**，逐题翻转 3 例，其中 2 例纯粹是尺子的形状
（`ho-t08` 在附带句里写了"当前登录状态无法确认"撞禁忌词；`ho-t10` 写"1～3 个工作日"而 gold 要「1至3」）。
**一次复跑的波动就是 ±1 题，所以 34 vs 35 落在噪声里**；旧路径多的那 1 分本来就是 `ho-c11` 走 HITL 中断
留下空答复、被采集器尺子判通过挣来的（换成逐题闸门的尺子，两臂同为 34/36）。
逐题差异表 回退 1 / 保持失败 1 / 翻正 1，闸门退出码 1（有回退就拦）。
两处差异能指到具体句子：`ho-t07` 是同义词（"由您承担" vs required「买家」），`ho-c01` 是**引用禁忌句去否定它**
（"预售不适用『48 小时内发出』的规则"）被字面尺子当成违规承诺——这一例在复跑里自己就好了。

复跑（~35 分钟一臂，模型走平台 key 换 id）：

```bash
bash agent/evaluation/run_all.sh legacy 36 deepseek-v4.1-flash legacy_off_dsv41.jsonl   # 旧路径，进程内
bash agent/evaluation/run_all.sh live 36 platform deepseek-v4.1-flash live_on_dsv41_final.jsonl
```

**为什么以前"答不了"**：当时 33 次最小补全全失败，我下了"没有任何一条模型路能出词"的结论——错在**猜模型名**。
先去问网关 `GET /models`（只读、零消耗）才知道这把 key 看得见 182 个模型，其中 `glm-5.3`、
`deepseek-v4.1-flash` 都能出词（`run_all.sh models 6` 现场可复跑）。这条教训比那两个可用模型更值钱：
**"外部依赖不可用"这种话，必须先按依赖自己的清单试过一遍再说**。
（`run_all.sh completion qwen-max,qwen-turbo` 仍在，`live-mock` 那套确定性替身臂也还在——管道验证不需要等模型。）

如果对方允许看"管道本身是不是真的通了"：

```bash
bash agent/evaluation/run_all.sh live-mock heldout 12   # 真 HTTP 往返，确定性替身，comparable=false
```

明确说这是替身：它证的是传输/序列化/记账/闸门格式，不证措辞。

## 如果对方追问"那长对话记忆到底比旧路径强多少"

同模型两臂也采到了（报告 §6f / §6g）。10 条对话，每条前 3 轮埋两个针（订单号 + 发票抬头），中间 8 轮填充，
最后一次探针"我最开始那笔单子编号是什么？抬头用的哪家？"：

| 臂 | 两针全中 | 说明 |
| --- | --- | --- |
| 旧路径（开关 off，进程内直调） | **0/10** | 十例答复**一字不差**是同一句兜底话，`route=order`：规则路由把复述题判成订单查询 → 未登录核验 → 返回"无法核实"。**根本没走到读历史那一步** |
| 新四 Agent 图 | **5/10** | 翻正 5 / **回退 0** / 缺题 0（`mem-diff` 闸门放行）|
| 同图，修完摘要输出预算之后（r5） | **9/10** | 空正文率 83%→5%、`watermark=0` 归零；回退仍 0，旧臂同批仍 0/10。剩下 mem-07 是"记得但不肯把编号说出来"的策略性自我消音 |

现场要说全的四点：

1. **旧路径 0/10 是路由赢过记忆，不是模型不行**——这一条最有说服力，因为它把"记忆"问题转成了"入口顺序"问题。
2. **新图那 5 个未全中要分开归因**，不能一句"机制有缺陷"糊过去：4 例答复里明写"不能凭记忆报编号"＝安全规则自我消音；1 例（mem-06 那一轮）是 24 条全在上下文却说"您没提供过订单号"＝真的长上下文利用失败；2 例的抬头半针是字面尺子的同义词盲区。⚠ `watermark=0` 那一类**原先被我归成"并发限流"，这个解释已被 §6g 收窄**：串行重采的 r2/r3 各自仍有 4 例、3 例为 0，而摘要跳过的原因当时只写进不落库的 trace，所以旧批次**无法再归因**，只能标 ⚠——现场这样讲反而更可信："我知道哪部分是测出来的，哪部分是猜的。"
3. **我没有去刷这个分**：改一行提示词就能把那 4 例自我消音刷成 PASS，但"复述客户自己给过的单号算不算越权"是产品决定，不是我能靠改卷子解决的。**这一条已经有决定：保持现状（复述仍被规则拦）**，所以 5/10 就是"这条规则下"的分数，`test_memory.py` 里那条断言钉着，放宽时必须一起改。
4. **成本要并列**：748,705 token vs 180,445 token（≈5.8k/轮 vs 1.4k/轮），整条对话墙钟 p50 **176.9s vs 33.0s**。
5. **合计稳、名单不稳**——这是最能挡追问的一句：同一套语料同一把尺子重采三遍，旧臂每次 0/10、新臂每次 5/10、回退每次 0，但"翻正的是哪 5 例"三批的交集**只有 mem-01**。所以能说"约一半的例子里两个针都能字面召回，且旧路径一例都召不回"，**不能说"mem-04 已经被我修好了"**（每例只跑一遍，n=1）。
6. **"两臂是同一段对话"现在有数据而不是承诺**：每行带 `script_sha`（12 句话按发送顺序的指纹）与逐轮转写（用户原话全文 + 答复前 120 字 + 单轮墙钟），`strict` 模式下不一致直接拦；被质疑时把附录翻到具体某一轮给他看。

```bash
bash agent/evaluation/run_all.sh live-mem 10 deepseek-v4.1-flash live_mem_dsv41.jsonl      # 新图臂
bash agent/evaluation/run_all.sh legacy 10 deepseek-v4.1-flash legacy_mem_dsv41.jsonl mem  # 旧路径臂（第 5 个参数=mem）
bash agent/evaluation/run_all.sh mem-diff                                                  # 逐题表 + 回退/缺题闸门（读已采数据，不需模型）
bash agent/evaluation/run_all.sh mem-diff agent/evaluation/runs/legacy_mem_dsv41_r3.jsonl \
     agent/evaluation/runs/live_mem_dsv41_r3.jsonl \
     agent/evaluation/runs/mem_diff_dsv41_r3_off_vs_on.md strict                            # §6g：带逐轮转写与语料指纹的那一批，自证性也进门禁
```

⚠ 两条臂**必须串行跑**（陷阱 #23）：并发时最先掉队的是摘要/复核这类辅助调用，而它的失败会被安全设计吸收，
症状恰好长得像"记忆机制失效"。另有一条不对称要主动讲：进程内那一臂没进 `lifespan`，摘要 worker 没跑，
所以这栏证明的是"当前 harness 下旧路径答不出复述题"，**不能外推成"现网旧路径也一定答不出"**。

## 收尾检查（每次演示后都跑一下再关终端）

```bash
bash agent/evaluation/run_all.sh pg          # 自建线程写入 → 删除 → 行数 0
```

演示脚本只写 `support_v2:t_demo:demo-*` 这类自建 key；`--postgres` 参数**故意不读 `$POSTGRES_DSN`**，
就是为了避免某次误跑静默往部署库写数据。要看"重启续聊"可以钉住线程名并留档：
`python -m agent.demo --postgres "$DSN" --thread demo-pinned --keep`（`--thread` 必须落在 `t_demo:` 前缀内）。
